# Лёгкий SQL

`SqlDatabase.sqlite(path)` использует стандартную библиотеку Python. Для
`SqlDatabase.postgres(dsn)` установите `muscles-data-sql[postgres]`. Эти операции не
требуют SQLAlchemy и `muscles-data`. Объект владеет одним соединением, которое
нужно закрыть. Транзакция фиксируется при успешном выходе и откатывается при
исключении. Параллельные вызовы транзакций из разных потоков сериализуются на
единственном соединении. Вложенная транзакция в том же потоке завершается
ошибкой. Имена столбцов результата должны быть уникальными: в JOIN используйте
псевдонимы. Активную транзакцию можно использовать только в открывшем её потоке.

Запросы используют SQL и параметры драйвера (`?` для SQLite, `%s` для
psycopg). Значения передаются отдельно от SQL; имена таблиц и полей нельзя
передавать параметрами. Произвольный SQL не применяет политики данных.

`ModelMapper(ModelClass, {"поле_модели": "столбец"})` преобразует явно
перечисленные поля через `Model.as_dict()`. При отсутствии столбца возникает
`KeyError`, при неизвестном поле модели — `ValueError`. Метод `from_records()`
преобразует набор строк. Mapper не выполняет валидацию, не генерирует SQL и не обеспечивает
авторизацию или проверку схемы.

Для необязательной интеграции установите `muscles-data-sql[data]` (требуется
`muscles-data` версии не ниже 0.2.0), зарегистрируйте `muscles.data.sql.data_adapter.NativeSqlFactory()`
в каталоге и настройте ресурс `native_sql`: `driver: sqlite` и `path` либо
`driver: postgres` и `url`/`url_env`. Запрашивайте `SqlTransactionPort`.
Список ресурсов не открывает соединение; транзакция и doctor открывают. При
первом подключении SQLite может создать файл, в том числе при doctor.

Дополнительный драйвер регистрируется без изменения адаптера:

```python
from muscles.data.sql import SqlDatabase, SqlDriverCatalog
from muscles.data.sql.data_adapter import NativeSqlFactory

def open_custom(options):
    connection = custom_driver.connect(options["url"])
    return SqlDatabase(connection, health_query="SELECT 1 FROM dual")

drivers = SqlDriverCatalog.with_defaults()
drivers.register("custom", open_custom)
catalog.register(NativeSqlFactory(drivers=drivers))
```

Фабрика получает разрешённые параметры ресурса и возвращает `SqlDatabase`.
`SqlDriverCatalog()` создаёт пустой каталог; `with_defaults()` регистрирует
SQLite и PostgreSQL. Повторная регистрация одного имени запрещена. Каталог
настраивается при запуске приложения, до конкурентной работы с ресурсами.
Рабочий пример с двумя независимыми ресурсами находится в
[`examples/native_resources.py`](../examples/native_resources.py).
Для СУБД с явным началом транзакции можно также передать `begin_sql`. Драйвер
должен предоставлять совместимый DB-API интерфейс соединения и курсора и
поддерживать используемый режим потоков; совместимость каждой новой СУБД нужно
проверить интеграционными тестами. SQL и параметры остаются нативными для неё.
`health_query` задаёт запрос диагностики для диалекта конкретной СУБД.

Репозитории на SQLAlchemy больше не входят в этот пакет.
Изменение зависимостей требует согласованного перехода существующих установок.

Для согласованного совместимого изменения уже применённой миграции модуль может
объявить кортеж `compatible_checksums` с точными контрольными суммами прежних
версий. Backend принимает только текущую или явно перечисленную сумму; другие
изменения и изменение файла после обнаружения остаются ошибкой.
