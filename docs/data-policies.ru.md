# Политики операций с данными

`DataRuntime.policies` содержит общий набор политик. Контекст конкретного
запроса передаётся в `SqlRepository` явно, вместе с этим набором:

```python
from muscles.data import DataOperationContext
from muscles.data.sql import SqlRepository

repo = SqlRepository(
    session,
    documents,
    policies=data_runtime.policies,
    context=DataOperationContext(subject_uid=user_id, attributes={"workspace_uid": workspace_id}),
)
```

Политики проверяются по порядку; отказ или некорректный результат прекращают
операцию. Условия чтения добавляются к запросу до сортировки и ограничения
числа строк. Условия обновления и удаления входят в `WHERE`; значения создаваемых
и изменяемых полей проверяются перед записью. Пакетные операции с политиками
используют защищённый путь и savepoint. Для `upsert` необходим полный набор
полей существующего первичного или уникального ключа.

`repo.explain()` показывает операцию, цель, имена полей и операторы без значений.
Она вызывает политики, но не выполняет SQL. Результат зависит от переданного
контекста и условий, поэтому его не следует считать проверкой будущего запроса
с другими параметрами.

Политики применяются только через `SqlRepository`. Прямые SQL-запросы,
включая `SqlDatabase` и прямые вызовы SQLAlchemy-сессии, их обходят. Условия
репозитория защищают его основную таблицу; подключённые через JOIN таблицы не
получают политики автоматически. Для обязательной изоляции на уровне БД
необходим отдельный механизм самой СУБД.

Не все SQL-операторы можно безопасно проверить над значениями записи: например,
`LIKE` при проверке записываемого поля отклоняется. `upsert` с политикой
выполняет чтение и затем запись, поэтому при параллельных операциях возможна
ошибка уникальности; приложение должно обрабатывать её в своей транзакции.
SQLAlchemy-репозиторий и общий контракт устанавливаются через
`muscles-data-sql[legacy]`; лёгкий SQL API может использоваться отдельно.
